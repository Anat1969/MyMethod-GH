# שיטת העבודה שלי
**[פתיחת האפליקציה](https://mymethod-gh.vercel.app/)**

מרעיון לאפליקציה חיה: שישה שלבים, מחברת החלטות ומצב הצגה לעמיתים ולתלמידים.

## הרצה
```bash
npm ci
npm run dev
npm run build
npx playwright install chromium
npm test
```

## מה נשמר
המחברת נשמרת ב-localStorage במכשיר בלבד, עם חיווי הצלחה או כישלון. אין סנכרון בין מכשירים. ייצוא JSON הוא גיבוי נייד; קישור שיתוף מכיל תמונת מצב ב-fragment של הכתובת. כל מי שמקבל קישור יכול לקרוא את התוכן. תמונת מצב אינה מתעדכנת אחרי שיתוף. המקבל יכול לייבא עותק למחברת שלו אחרי אישור החלפה.

## AI
פונקציית Edge ב-`api/distill.ts` פונה ל-Gemini החינמי. יש להגדיר `GEMINI_API_KEY` ב-Vercel, ב-Production וב-Preview. אין מפתח בדפדפן. Claude הוא גיבוי אופציונלי בלבד, הדורש `ANTHROPIC_API_KEY` וגם `CLAUDE_FALLBACK_MODEL`. לא מוגדר ספק נוסף ולא מתבצע חיוב מכוון במסלול הראשי. אם אין מפתח Gemini, הממשק מודיע על כך וממשיך לאפשר תיעוד ידני.

נשלחים רק רעיון, קהל, שלב, החלטה ונימוק, לאחר סימון מפורש שהטקסט ציבורי. הראיה ויומן ההערות אינם נשלחים. פלט מובנה נבדק גם בשרת, כולל מגבלות אורך של תקן הזיקוק. ההצעות אינן מחליפות שיקול דעת.

מגבלת הקצב המקומית לפונקציה היא 3 בקשות לדקה לכתובת IP בכל מופע Edge; זו אינה מגבלה מבוזרת לכל החשבון. מכסת הספק החינמית מוסיפה גבול חיצוני. לשימוש ציבורי נרחב יש להוסיף מגבלת WAF מבוזרת לפני הגדלת החשיפה.

## מבנה
- `src/data/method.ts`: שלבים, מקורות ודוגמאות.
- `src/components/`: השיטה, מחברת, הצגה, מקורות ורכיב הלוגו המשותף.
- `src/lib/storage.ts`: אימות סכמה, שמירה, גיבוי ושיתוף.
- `api/distill.ts`: זיקוק דרך Edge.
- `public/`: PWA ועותק רכיב הלוגו לבדיקות.
- `tests/`: תרחישי Playwright.

## פריסה
ענף הייצור הוא `main`. `npm run build:github` מפיק עותק סטטי לתיקיית `app/`; פונקציית ה-AI פועלת ב-Vercel בלבד. Action מעדכן את העותק אחרי מיזוג. תצוגת GitHub הסטטית אינה מפעילה AI.

החלטה ומקורות: [docs/spec.md](docs/spec.md). תיעוד בדיקות: [docs/verification.md](docs/verification.md).
